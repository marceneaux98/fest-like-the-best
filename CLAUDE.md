# Fest like the Best: context for Claude

Static web app (no framework, no build) for Festival International de Louisiane 2026 patrons. See README.md for running and data updates.

## Decisions already made with the user
- Product name / tagline: **"Fest like the Best"** (brand script, next to the logo; in page titles).
- Brand kit: Blue #1984C7, Purple #542E91, Orange #F26631. Fonts: Futura Bold Italic (headlines), Futura Medium (text), Ando (condensed display), Thirsty Script (accent). Free stand-ins: Jost, Saira Condensed, Yellowtail. Full-colour logo on white; reversed/white on dark.
- Stage order everywhere: Internationale, Fais Do Do, Lafayette, Biergarten, FrancoSphere, Pavillon, Scène des Jeunes (driven by the order in locations.json).
- Languages: menu lists Français first; English is the default; also Español, Tiếng Việt. All UI strings live in i18n.js; never hard-code English in pages.
- Merch: three booths (Pavillon, Lafayette, Fais Do Do). The app suggests a time automatically (break that fits detour + shopping with ≥3 min spare, else before first set); patron can accept, pick another time, or decline.
- Overlaps / tight connections: patron chooses leave early, split the difference, or stay to the end.
- Picking an artist already in the plan opens a "Switch / Keep both / Cancel" prompt; grid blocks list the artist's other shows at the bottom ("Also: …", ✓ = in plan).
- Picking or changing options must not reset scroll position or re-zoom the map.

## Working notes
- Schedule data: source of truth is Monday.com (board IDs/columns in `feed.config.json`). `build_feed.py` writes `data/schedule.json` + `data/artists.json`; pages load them at runtime via `FIL.ready()`. The 2027 lineup is confidential until announced: never set `public_from` for 2027 or commit `data/preview/`; the sync workflow is manual only. The Artist board holds SSNs and payment details, so only allowlisted columns are ever read.
- The map IS the festival poster: `assets/sitemap.svg` (layers `#layer-background/zones/streets/features/labels/legend/logo`; map icons are `g.icon[data-kind]`), shown upright with Leaflet `CRS.Simple` (lat = -y, lng = x, poster points on the 774×603 page). No street tiles, no GPS on the map. Stage pins are fractions of the page in `overlay.js` (`stages`, optional `entrances`). Routes drawn on the map come from `assets/poster-routes.json`, traced along the drawn streets by `tools/poster-routes.html` (re-run and save after moving a pin or changing the map). Walking distance/time are measured along those drawn lines (`metres`, with the pin hops) on the poster fitted to OpenStreetMap streets (`geo`, fitted in the editor from `tools/osm-streets.json`); pages read them via `FIL.walk`. `routes.js` (`python build_routes.py`, street router between the same entrances) is the check and fallback: run it after routes are saved, before publishing. Distances show in feet for English. `site-overlay.js` = `SiteMap.create/shape/draw/join`. Shops (merch booths, Marché des Arts, Marché du Monde) live in `poster-routes.json` (`shops`, `pins`, estimated `metres`); My Day lets the patron pick the kind of shopping stop. Routes may use the thin side streets (cost x1.6); default entrances stay on festival streets, hand-placed ones may be on side streets. Stages can have several entrances. `build_sitemap.py` builds the SVG from the designer's vector PDF via `tools/pdf2svg.html`; keep the raster `assets/sitemap.pdf` only for reference.
- Shared code lives in `common.js` (`FIL.esc`, `FIL.toMin`, `FIL.store`, `FIL.stages`/`stageById`/`stageColor`, brand bar from `<div class="brand-bar" data-page="…">`) and `brand.css` (colour tokens, fonts, base styles). Stage names, colours and order come from `locations.json` only. Pages keep only page-specific CSS/JS.
- **The site is live with real users** (shared publicly on 2026-11-27). `main` deploys to GitHub Pages within a minute, so code changes go on a branch (preferably a worktree, so the shared folder stays on `main`) and into a pull request; merge only when the Checks workflow is green and Max has seen it. Data publishes (route editor saves, the Monday schedule sync) still go to `main`, only when Max says so. Keep saved state compatible: never rename `fil-*` localStorage keys or change set ids without a migration, or people lose their picks and shared plan links break.
- Git: `main` is live; commit identity set per-repo. This machine has `python` (Store install), not the `py` launcher, Git lives at `C:\Program Files\Git\cmd` and the GitHub CLI at `C:\Program Files\GitHub CLI` (both may need adding to PATH in a fresh shell).
- Offline: `sw.js` keeps the site on patrons' phones (data network-first with a saved fallback, everything else saved-first and refreshed in the background). It is off on localhost unless a page is opened with `?sw=1` (`?sw=0` clears it). When adding a file every page needs, add it to `CORE` and raise `VERSION` in `sw.js`.
- Serve with `python serve.py` (no-cache headers). Test in a separate origin (http://127.0.0.1:8765) so test picks don't overwrite the user's saved picks on http://localhost:8765. localStorage keys start with `fil-`.
- Python here may be old (3.8) and pip installs may be blocked; keep scripts standard-library only.
- Check pages at phone width (375px) as well as desktop; `phones.html` shows all three.
